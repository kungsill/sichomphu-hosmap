# Smart Hospital Navigation — โรงพยาบาลสีชมพู

ระบบแผนที่นำทางผู้ป่วยภายในโรงพยาบาล เชื่อมต่อ HOSxP V4 แบบอ่านอย่างเดียว
เจ้าหน้าที่ทำงานใน HOSxP ตามปกติ ระบบจะอ่านการส่งตรวจ/รับบริการ/ส่งต่อ แล้วปรับปลายทางบนแผนที่ของผู้ป่วยให้อัตโนมัติ

## เริ่มใช้งาน (โหมดสาธิต)

```
run.bat          (Windows)
./run.sh         (Linux)
```

เปิด http://localhost:8090 — โหมดสาธิตจะจำลองผู้ป่วยตั้งแต่ 07:30 (นาฬิกาเดินเร็ว 12 เท่า) และเริ่มวันใหม่ทุกครั้งที่เปิดโปรแกรม

| หน้า | ใช้ทำอะไร | ผู้ใช้ |
|---|---|---|
| `/` | แผนที่ 3 มิติ ตำแหน่ง/สถานะผู้ป่วย ความหนาแน่น จุดบริการ ค้นหาคิว/HN พิมพ์ใบนำทาง | เจ้าหน้าที่ |
| `/builder` | Map Builder: อัปโหลดแปลน วาดห้อง ปักจุดนำทาง เชื่อมทางเดิน ลิฟต์/บันได จับคู่รหัส HOSxP ทดสอบเส้นทาง เผยแพร่ | IT |
| `/slip/{VN}` | ใบนำทางพร้อม QR Code (เครื่องพิมพ์ 80 มม.) | เจ้าหน้าที่ |
| `/t/{token}` | หน้าที่ผู้ป่วยเปิดจาก QR: ปลายทาง เส้นทางเดิน สถานะคิว ตัวเลือกรถเข็น | ผู้ป่วย |

## โครงสร้าง

```
HOSxP V4 ──(SELECT อย่างเดียว ทุก 3 วินาที)──► Integration Worker ──► ฐานข้อมูล hospital_navigation
                                                 (app/hosxp/worker.py)        │
                                                                              ▼
                                   หน้าจอเจ้าหน้าที่ / มือถือผู้ป่วย ◄── SSE ── FastAPI (app/main.py)
```

- `app/hosxp/worker.py` — เทียบสถานะของแต่ละ VN กับรอบก่อน แล้วสร้างเหตุการณ์ (`sent`, `in_service`, `service_done`, `left`, `order_added`, `order_done`, `finished`) ไม่เกิดเหตุการณ์ซ้ำ และกู้สถานะเองหลังระบบล่มหรือเชื่อมต่อใหม่ VN ที่หายจากผลลัพธ์ต้องหายติดต่อกันหลายรอบก่อนจะปิด
- `app/mapdata.py` — แผนที่ฉบับร่าง/ฉบับเผยแพร่ และคำนวณเส้นทางด้วย Dijkstra บนกราฟจุดนำทาง ไม่ใช่ลากเส้นตรงทะลุผนัง รองรับข้ามชั้นและเส้นทางรถเข็นที่เลี่ยงบันได
- `app/status.py` — ลำดับคิว เวลารอโดยประมาณ (เรียนรู้จากเวลาให้บริการจริง) ความหนาแน่น และขั้นตอน
- `app/hosxp/mock.py` — HOSxP จำลองสำหรับสาธิต ใช้ชื่อตาราง/คอลัมน์เลียนแบบ HOSxP
- `static/js/iso.js` — ตัววาดแผนที่ 3 มิติ (Canvas) ไม่ต้องใช้อินเทอร์เน็ตหรือ Google Maps
- `hosxp_queries.ini` — คำสั่ง SQL ที่ใช้อ่าน HOSxP **แก้ไขได้โดยไม่ต้องแก้โค้ด**

ตารางในฐานข้อมูลระบบนำทาง: `buildings`, `floors`, `rooms`, `map_nodes`, `map_edges`, `hosxp_room_mapping`, `map_versions`, `patient_visits`, `patient_status`, `patient_events`, `navigation_tokens`, `sync_state`
(ระบบสร้างตารางเองเมื่อเริ่มทำงาน ทั้งบน SQLite และ MySQL/MariaDB)

## กฎเลือกปลายทาง

1. ปกติ ปลายทางคือหน่วยบริการปัจจุบันใน HOSxP (`cur_dep`)
2. ถ้าแผนกเดียวมีหลายห้องและ HOSxP ไม่บอกห้องย่อย ระบบจะ **พาไปพื้นที่รอของแผนก** ไม่เดาห้อง
3. ถ้ารับบริการที่หน่วยปัจจุบันเสร็จแล้ว แต่มีงานค้างหลายห้อง (เช่น LAB และ X-ray) จะเลือกห้องที่ "กำลังตรวจ" ก่อน แล้วตาม `priority` แล้วตามระยะทาง ไม่ใช้ห้องล่าสุดเป็นปลายทางโดยอัตโนมัติ
4. เมื่อจบ Visit แผนที่จะนำทางไปทางออก และเก็บประวัติทั้งหมดไว้ใน `patient_events`

## เชื่อมต่อ HOSxP V4 จริง

1. สร้างบัญชี MySQL ที่มีสิทธิ์ `SELECT` เท่านั้น (ระบบสั่ง `SET SESSION TRANSACTION READ ONLY` ซ้ำอีกชั้น)
2. คัดลอก `.env.example` เป็น `.env` แล้วตั้ง `HOSXP_MODE=mysql`, `HOSXP_DB_URL`, `PUBLIC_BASE_URL`, `STAFF_PASSWORD`
3. **ตรวจ `hosxp_queries.ini` กับฐานข้อมูลทดสอบก่อน** ให้เจ้าหน้าที่กดส่งตรวจ รับผู้ป่วย ส่งกลับ และจบงาน แล้วดูว่าคอลัมน์ใดเปลี่ยน
   - `ovst.cur_dep`, `ovst.cur_dep_busy`, `ovst.cur_dep_time` ใช้ตามที่ รพ. ใช้จริงหรือไม่
   - ใช้อะไรบอกว่า "จบ Visit" (ค่าเริ่มต้นคือ `ovst.ovstost` ไม่ว่าง)
   - HOSxP บันทึกห้องตรวจย่อย (ห้อง 1–5) ไว้ที่ใด ถ้ามี ให้คืนค่าเป็น `room_hint`
   - คำสั่งตรวจ LAB/X-ray อยู่ตารางใด เพื่อเขียน `orders`
4. ใน Map Builder แท็บ "จับคู่ HOSxP" กด "ดึงรายชื่อหน่วยบริการจาก HOSxP" แล้วแทนรหัสตัวอย่าง (001, 002, 010 …) ด้วยรหัสจริง
5. ทดลองเริ่มเฉพาะ OPD, LAB, X-ray, การเงิน และห้องยา เมื่อสถานะบนใบนำทางตรงกับ HOSxP จึงขยายไปอาคารอื่น

## การติดตั้งบน Server โรงพยาบาล

- ใช้ฐานข้อมูลระบบนำทางแยก (`NAV_DB_URL` เป็น MySQL/MariaDB) ไม่เขียนลงฐาน HOSxP
- ตั้ง `PUBLIC_BASE_URL` เป็นที่อยู่ที่มือถือผู้ป่วยเข้าถึงได้ผ่าน Wi-Fi โรงพยาบาล
- ตั้ง `STAFF_PASSWORD` ก่อนเปิดใช้งาน (หน้าจอเจ้าหน้าที่แสดง HN) — หน้าผู้ป่วยเข้าได้ด้วย token สุ่มเท่านั้น ไม่มีเลขบัตรประชาชนใน URL และหน้าผู้ป่วยแสดงคนอื่นแบบนิรนาม
- ถ้าวาง reverse proxy (nginx) ให้ปิด buffering ของ `/api/stream` และ `/api/t/*/stream` (SSE)
- ทดสอบภาระฐานข้อมูล HOSxP ก่อนลด `POLL_SECONDS` ให้ต่ำกว่า 3 วินาที
